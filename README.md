# 迷你知识库问答（检索式 QA / RAG 的最小版本）

一句话：**只用 Python 标准库**实现的检索式问答小项目——用户用自然语言提问，系统从 40 条本地知识中找出最相关的一条来回答；当知识库里没有相关内容时，它会明确回答「没有找到相关答案」，而不是硬答。

## 项目背景与要解决的问题

大语言模型直接回答问题时容易「一本正经地胡说」。检索增强生成（RAG）的思路是：先从资料库里检索相关内容，再让模型基于检索结果回答。本项目用最小实现复现 RAG 的**检索环节**，并回答三个工程问题：

1. **问法和原文不一样怎么找？** 用户不会照着知识库的措辞提问，需要用字符级特征做模糊匹配（字符 2-gram TF-IDF + 余弦相似度）。
2. **知识库里没有答案怎么办？** 只靠相似度排序永远会返回一个「最像」的条目，必须加拒答机制（Top-1 相似度阈值）。
3. **怎么证明它有效？** 自建 50 条评测集：40 条知识库问题的同义改写（考察库内命中）+ 10 条库外问题（考察拒答），并与「不设拒答、永远硬答」的 baseline 对比。

## 技术方法

- **文档表示**：把每条知识的 `question` 和 `answer` 拼成一个文档；文本转小写、去掉标点和空白后，切成相邻两个字符的 2-gram（例如「机器」→ `机器`、`器学`…）。
- **TF-IDF**：统计每个 bigram 出现在多少条文档中（df），按 `idf = log((N+1)/(df+1)) + 1` 计算（N = 知识库条数 = 40）；`tf × idf` 后做 L2 归一化，得到每条知识的单位向量。查询用同一套 idf 向量化，词表外的 bigram 直接丢弃。
- **检索**：查询向量与 40 个文档向量算余弦相似度（两个单位向量的点积），取 Top-3。
- **拒答**：Top-1 相似度低于阈值时，输出「没有找到相关答案。」。阈值在 **0.15–0.45** 范围内按步长 0.01 网格搜索（31 个候选），选择标准是**最大化「库内 Top-1 命中率 + 库外拒答正确率」**；同分时优先拒答正确率更高（更安全），仍同分则取较小阈值（避免过度拒答）。
- **指标口径**：库内题被拒答按「未命中」计；Top-3 命中要求该题未被拒答、且正确条目出现在 Top-3 中。

## 快速开始

无需安装任何第三方包，Python 3.8+ 即可（开发环境 Python 3.15.2，Windows）：

```bash
cd mini-kb-qa

# 1) 离线评测：阈值搜索过程 + 全部指标 + badcase 示例
python main.py --eval

# 2) 单条提问：输出 Top-3（问题/相似度/答案），低分时拒答
python main.py --ask "怎么报名训练营"
python main.py --ask "今天天气怎么样"
```

入口脚本已处理 Windows 控制台编码问题（`sys.stdout.reconfigure(encoding="utf-8")`），文件均为 UTF-8。

## 实测结果

数据规模：**40 条知识 / 50 条评测问题（40 条库内同义改写 + 10 条库外问题）**。以下数字全部来自本机实际运行 `python main.py --eval` 的输出（词表 2840 个 bigram，文档平均长度 101.3 个 bigram）：

| 指标 | 结果 |
| --- | --- |
| 库内 Top-1 命中率 | **0.800（32/40）** |
| 库内 Top-3 命中率 | **0.925（37/40）** |
| 库外拒答正确率 | **0.800（8/10）** |
| 库外误答率（设置阈值后） | **0.200（2/10）** |
| 最优拒答阈值 | **0.15**（31 个候选中的综合分最高者，综合分 1.6000） |

与「不设拒答」的 baseline 对比：

| 策略 | 库内 Top-1 命中率 | 库内 Top-3 命中率 | 库外误答率 |
| --- | --- | --- | --- |
| baseline：永远返回 Top-1 | 0.825（33/40） | 0.975（39/40） | **1.000（10/10）** |
| 本方法：Top-1 阈值拒答 | 0.800（32/40） | 0.925（37/40） | **0.200（2/10）** |

代价是库内损失 1 条本来能答对的题、2 条 Top-3 命中，换来库外误答率从 100% 降到 20%——这正是「敢说不知道」的价值。

`--eval` 输出的 10 条 badcase 构成：**库内 Top-1 错误 5 条**（正确条目都还在 Top-2/3，属于排序问题）、**库内被误拒 3 条**（同义改写与原文重合太少，相似度低于 0.15）、**库外误答 2 条**（「报名训练营需要准备什么材料」「训练营报名需要什么条件」话题与知识库太近，被当成了报名问题）。

## 局限与改进

1. **知识库与评测集均为本人自建的小样本（40 条知识 / 50 条问题）**，只能验证流程是否跑通，不能代表真实业务效果。
2. **改写样本有限**：库内只有 40 条同义改写，1 条对错就会让 Top-1 指标波动 2.5 个百分点，指标置信度不高，也没做交叉验证。
3. **同义词只能靠字面相似度**：字符 2-gram 无法理解「学费 ↔ 费用」「报错 ↔ 异常」「岗位 ↔ 工作」这类真正的语义同义，因此出现 3 条库内题被误拒（如「参加训练营要花多少钱」相似度仅 0.134，Top-1 其实找对了条目）。
4. **相似度绝对值偏低**：文档是「问题+答案」拼接（答案较长，约 100 个 bigram），会稀释问题与查询的重合度，导致阈值搜索最优值落在网格下界 0.15。说明当前打分的区分度有限，继续调阈值收益不大；可考虑给问题字段加权、改用 BM25 的长度归一，或引入句向量语义检索（但那就需要第三方模型/依赖了）。
6. **阈值是在同一份评测集上选出来的**：31 个候选阈值用 50 条评测题搜索，再用同样的题报指标，属于轻微过拟合；更严谨的做法是划出 dev 集选阈值、测试集只用来报数。样本再大一些时这个偏差会显现。
5. **单一标量阈值无法处理「话题相近但知识库没有答案」**：2 条库外问题因含「训练营」「报名」等词被误答。改进方向是加意图分类、关键词必含条件或「检索结果与问题主题一致性」二次校验。

## 目录结构

```
mini-kb-qa/
├── main.py                     # 入口：TF-IDF 检索 + 阈值拒答 + 评测
├── data/
│   ├── kb.csv                  # 40 条知识（id, question, answer）
│   └── eval_questions.csv      # 50 条评测问题（question, expected_id；库外为 NONE）
└── README.md
```

- `main.py` 中 `--eval` 会依次打印：阈值网格搜索表 → 最终指标 → baseline 对照 → 10 条 badcase；`--ask` 会输出 Top-3 检索结果与最终回答/拒答结论。
- 评测集里的 `expected_id` 对应 `kb.csv` 的 `id`，`NONE` 表示知识库外问题。
